# Credit Scoring HELOC

Система кредитного скоринга, которая оценивает риск клиента с помощью методов машинного обучения и формирует объяснение принятого решения.

В качестве основной модели используется **XGBoost**. Для интерпретации отдельных предсказаний применяется **SHAP**, а для формирования понятного текстового объяснения результатов используется **GigaChat**.

## Возможности

- обработка данных кредитной истории;
- предобработка и обработка пропущенных значений;
- обработка специальных значений исходного датасета;
- обучение нескольких моделей машинного обучения;
- оценка качества моделей;
- сравнение моделей;
- подбор порога классификации;
- предсказание кредитного риска для нового клиента;
- объяснение предсказания с помощью SHAP;
- генерация текстового объяснения с помощью GigaChat;
- REST API на FastAPI;
- веб-интерфейс на Streamlit;
- запуск приложения в Streamlit Community Cloud.

## Используемые модели

В проекте реализовано несколько моделей:

- **XGBoost** — основная модель кредитного скоринга;
- **Logistic Regression** — базовая модель для сравнения;
- **Neural Network** — дополнительная модель для сравнения.

Для пользовательского предсказания используется XGBoost.

## Интерпретация предсказаний

Для объяснения отдельных предсказаний используется **SHAP**.

Система определяет наиболее значимые признаки, повлиявшие на результат модели, и показывает:

- значение признака;
- направление влияния на кредитный риск;
- значение SHAP.

На основе этих факторов формируется текстовое объяснение с помощью **GigaChat**.

## Как работает система

### 1. Предобработка данных

Исходные данные проходят предварительную обработку.

В исходном датасете используются специальные значения `-7` и `-8`. Они рассматриваются отдельно: для признаков создаются специальные бинарные признаки, после чего специальные значения заменяются на пропуски.

Пропущенные значения заполняются медианами, рассчитанными на обучающей выборке.

### 2. Обучение моделей

В `train.py` выполняются следующие этапы:

1. загрузка датасета;
2. разделение данных на обучающую, валидационную и тестовую выборки;
3. предобработка признаков;
4. обучение XGBoost;
5. обучение Logistic Regression;
6. обучение нейронной сети;
7. подбор порога классификации;
8. оценка качества моделей;
9. сохранение обученных моделей и необходимых артефактов.

### 3. Предсказание

При вводе данных нового клиента веб-интерфейс передаёт данные в систему инференса.

Общий процесс:

```text
Данные клиента
      ↓
Предобработка
      ↓
XGBoost
      ↓
Вероятность плохого кредита
      ↓
Порог классификации
      ↓
Bad / Good
```

### 4. Объяснение решения

После получения предсказания система определяет наиболее значимые факторы с помощью SHAP.

```text
Предсказание XGBoost
        ↓
       SHAP
        ↓
Основные факторы решения
        ↓
     GigaChat
        ↓
Текстовое объяснение
```

В результате пользователь получает не только предсказание модели, но и объяснение того, какие характеристики клиента оказали наибольшее влияние на решение.

## REST API

Для взаимодействия с моделью реализован REST API на **FastAPI**.

Основная точка API:

```text
POST /predict
```

На вход передаются характеристики клиента, а API возвращает:

- предсказание;
- вероятность плохого кредита;
- используемый порог классификации;
- основные SHAP-факторы;
- текстовое объяснение GigaChat.

## Веб-интерфейс

Пользовательский интерфейс реализован с помощью **Streamlit**.

Интерфейс позволяет:

1. ввести характеристики кредитной истории клиента;
2. отправить данные на предсказание;
3. получить вероятность плохого кредита;
4. увидеть итоговое решение модели;
5. посмотреть основные факторы, повлиявшие на решение;
6. получить текстовое объяснение результата.

## Запуск локально

### 1. Клонирование репозитория

```bash
git clone https://github.com/donrumata05/credit-scoring-heloc.git
cd credit-scoring-heloc
```

### 2. Создание виртуального окружения

```bash
python -m venv .venv
```

Для Windows:

```powershell
.venv\Scripts\activate
```

### 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 4. Настройка GigaChat

Для работы генерации текстовых объяснений необходимо указать необходимые секретные параметры GigaChat.

Локально они могут храниться в файле `.env`.

Файл `.env` не добавляется в Git-репозиторий.

### 5. Запуск Streamlit

```bash
streamlit run app.py
```

После запуска Streamlit выведет адрес локального веб-приложения.

### 6. Запуск FastAPI

В отдельном терминале:

```bash
uvicorn api:app --reload
```

После запуска API будет доступно по адресу:

```text
http://127.0.0.1:8000
```

## Streamlit Community Cloud

Приложение также развёрнуто в **Streamlit Community Cloud**.

Основной файл приложения:

```text
app.py
```

Для облачного запуска секретные данные GigaChat не хранятся в Git-репозитории. Они добавляются через **Secrets** в настройках Streamlit Community Cloud.

## Сохранённые артефакты

Обученные модели и необходимые для инференса параметры сохраняются в директории `artifacts/`.

Основные файлы:

| Файл | Назначение |
|---|---|
| `xgb_model.json` | обученная модель XGBoost |
| `xgb_threshold.pkl` | порог классификации XGBoost |
| `nn_model.pth` | веса нейронной сети |
| `nn_threshold.pkl` | порог классификации нейронной сети |
| `feature_names.pkl` | порядок признаков |
| `imputer_values.pkl` | медианные значения для заполнения пропусков |
| `results.csv` | результаты сравнения моделей |

Сохранение артефактов позволяет выполнять предсказания без повторного обучения моделей.
